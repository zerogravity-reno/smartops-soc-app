## The approved plan

Mohammed's three asks:
1. Unconnected or inaccessible tools (edr, ndr) shouldn't come up at all.
2. Why doesn't the Splunk agent use `tstats`?
3. If a question needs endpoint/EDR data, why doesn't it just search Splunk?

### What the investigation found (verified on live runs and with read-only Splunk queries)

**Issues 1 and 3 share one root cause:** unconnected families reach the model through text that ignores configuration.
- **`engine/src/smartops/domains.py` descriptions.**
  - `SIEM.description` says *"Do NOT use … for live host process detail (use investigate_edr)"*. That tells the Broker EDR exists **and** pushes host and process questions away from Splunk, which holds Sysmon EID 1 and 4688.
  - `EDR.description` and `NDR.description` point at each other's tools.
- **`engine/src/smartops/subagents/__init__.py:205`:** the subagent's report instructions say *"gaps: any other domain that could close a gap you hit"*. `SubagentAnswer.gaps` is `list[ToolFamily]` (`engine/contracts/src/contracts/subtask.py:390`), so siem advises `edr`/`ndr`.
- **The Broker prompt** (`broker.py:132`, `_SYSTEM_PROMPT`) says *"If a specialist reports gaps that another domain could close, you may dispatch that domain as well."* That turned siem's EDR advice into EDR plans: 3 `investigate_edr` calls in `cecd266a`, and "EDR not available" in the classifications.
- **Already in place:** `plan_fetch` refuses unconfigured families (`_plannable`, `58d39c3`). Gap records (`_domain_gaps` in `subagent_analysts/analyze.py`) go to `findings.json` only and never reach the Analyst payload.

**Issue 2: `tstats` works, and the agent does use it** (143 `tstats` calls across runs `cecd266a`, `072fd610`, `04a15495` and `a8118db9`). Three confirmed causes let it down:
- **Non-CIM field names return 0 rows silently.** 34 of 143 calls used `Processes.host` or `All_Traffic.host`. The CIM field is `dest`. The same query returned 0 rows `by …, Processes.host` and 1 row `by …, Processes.dest`.
- **Narrow windows.** About 40 of the 47 `tstats` calls in the repeat runs searched `12:04–12:06Z` (detection time); the activity was at 11:55Z. That's the context pipeline's `event_time` (issues-report P1), and **out of scope here**.
- **`TstatsDeadEndGuard` overreacts** (`engine/src/smartops/guards.py:374`). Any zero-row `tstats`, however narrow its filter or window, marks the whole data model dead and cancels every later `tstats` against it. In `072fd610`, 34 `tstats` were blocked although `Endpoint.Processes` returned up to 106 rows on wider windows.
- **Ruled out:** the Splunk environment and the time pin. `Endpoint` is accelerated and shared globally (`Splunk_SA_CIM`). The alert's own `tstats` rule returns its row through the Broker's MCP connection. A run's `tstats` query, replayed with its pinned epoch window, returns rows.

## Summary

Reconnects the Analyst to the Tool Broker, which runs on the official Splunk MCP server again. The Analyst's tasks now reach the Broker through the `task-input.v1` contract. Two live investigations ran end to end through the UI with the handshake intact (`sent → fetched → returned`).

### Integration
- **`webapp/services/run_trace.py`** converts the Analyst's tasks into a task file and records the handshake in one `investigation.jsonl` per run. It checks the Broker's exit code. A run never falls back to another run's artifacts, which is how 11 loops were once judged on an 8-day-old run.
- **The webapp** streams Broker output over SSE. The UI shows Analyst and Broker lanes with a handshake stamp per loop, and model and log text is escaped before rendering.
- **The Splunk Web scraper** is replaced by the official MCP server again (17 tools).
- **Secrets** are removed from `start_server.bat`, `webapp/main.py` and `.env.example`.

### Bugs found on the live runs and fixed
- **Wrong time window.** The seed's `event_time` was the browser's clock, and the Analyst dropped a `+03:00` offset. The investigation searched 3 hours after the alert and returned a false positive. `event_time` is now the alert's `_time` in UTC, and the Analyst prompt anchors every window on it.
- **UTC rows.** Sub-analysts now see row times in UTC, the same zone as the task window.
- **Missing tools.** `plan_fetch` refuses steps for families that have no tool behind them (the Broker had called the missing `investigate_edr` three times) and points the model to siem instead.
- **Demo alert.** The form no longer ships with a demo alert, and an empty form is refused.

### Tool Broker: only connected tools, reliable `tstats`
- **Unconnected tools never reach a model.** Domain descriptions, the subagent `gaps:` instruction, and the `plan_fetch` and `TaskClassification` schemas named `edr`/`ndr` whatever was configured. On `cecd266a` that produced 3 `investigate_edr` calls and steered host questions away from Splunk. These now list configured families only. With EDR absent, the Splunk description says endpoint telemetry (Sysmon EID 1, 4688) is indexed there.
- **`tstats`.** The siem prompt lists the CIM field names per data model. `TstatsDeadEndGuard` marks a data model dead only after an *unfiltered* empty query; on `072fd610` one narrow empty query had cancelled 34 later ones. A `tstats` naming `host`, `Computer`, `CommandLine`, `Image` or `ParentImage` is cancelled with the CIM field to use (34 of 143 calls had returned 0 rows silently that way).
