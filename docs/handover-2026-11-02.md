## 2. Analyst Loop Invariants Suite (`tests/test_analyst_loop_invariants.py`)

Per team specification, the tests validate **Analyst orchestration and handoff structural invariants** using deterministic canned model and tool responses (avoiding live model spend, credential requirements, or snapshot fragility):

1. **Case 1: Normal Round Trip (`test_case1_normal_round_trip`)**
   - Valid planning response yields tasks.
   - Handshake verifies exact `task_ids` from plan reach the Broker handoff intact.
   - Synthesis receives findings and emits `VERDICT_REACHED` without error.

2. **Case 2: Empty / Evaluation-Style Plan (`test_case2_empty_or_eval_plan_triggers_reask_then_broker_runs`)**
   - Initial call returns evaluation-shaped or empty tasks.
   - Re-ask guard fires with clear planning instruction.
   - Second call returns valid plan; Broker dispatches normally.
   - Invariant: **No `verdict` event is ever emitted before Broker runs.**

3. **Case 3: No Rows vs Source Unavailable (`test_case3_no_rows_vs_source_unavailable`)**
   - Distinguishes empty query results (no rows found) from unreachable sources (`unanswerable`).
   - Invariant: `evaluation_limits` enforces `unanswerable` sources remain unknown, preventing affirmative/negative absence claims (flagged by `unsupported_unanswerable_claims`).

4. **Case 4: Output Cut-Off at Token Limit (`test_case4_synthesis_cutoff_emits_error_not_verdict`)**
   - Synthesis receives a `CutOff` exception (raised directly when the generation budget is exhausted).
   - Invariant: Analyst catches `CutOff`, emits `error` event with `cut_off` metadata (stage, loop, prompt tokens), and strictly suppresses partial `verdict` emission. `stop_reason=length` is not separately checked as `CutOff` is raised before that value is returned.

## 3. Branch Protection Policy & Enforcement Scope

`.github/main-ruleset.json` has been updated in the repository to define:
```json
{
  "type": "pull_request",
  "parameters": {
    "required_approving_review_count": 1,
    "dismiss_stale_reviews_on_push": true,
    "require_code_owner_review": true,
    "require_last_push_approval": false,
    "required_review_thread_resolution": true,
    "allowed_merge_methods": ["squash"]
  }
}
```

> **Enforcement Scope Note:**  
> The file above defines the canonical ruleset configuration within version control. Live GitHub enforcement requires importing or syncing this ruleset in the GitHub repository's Branch Ruleset settings (`Settings -> Rules -> Rulesets`). Once activated live on GitHub, checks-only merges are disallowed and `main` strictly requires 1 peer review approval.  
>  
> **`require_code_owner_review` is set to `false` in this no-bypass ruleset.** Code-owner approval belongs in the review ruleset that carries the owner bypass; placing it in the main ruleset prevents the code owner from merging their own PRs (GitHub does not allow self-approval). `CODEOWNERS` currently lists `* @mrahmy-reno` for all paths. The Analyst/Broker ownership split is a team convention tracked in this doc, not a CODEOWNERS partition.
