## 2. E2E Integration Suite (`tests/test_analyst_broker_e2e.py`)

Per Mohamed Rahmy's specification, tests validate **structural rules and invariants**, not brittle snapshot comparisons:

1. **Case 1: Normal Round Trip (`test_case1_normal_round_trip`)**
   - Valid planning response yields tasks.
   - Handshake verifies exact `task_ids` from plan reach the Broker intact.
   - Synthesis receives findings and emits `VERDICT_REACHED` without error.

2. **Case 2: Empty / Evaluation-Style Plan (`test_case2_empty_or_eval_plan_triggers_reask_then_broker_runs`)**
   - Initial call returns evaluation-shaped or empty tasks.
   - Re-ask guard fires with clear planning instruction.
   - Second call returns valid plan; Broker dispatches normally.
   - Invariant: **No `verdict` event is ever emitted before Broker runs.**

3. **Case 3: No Rows vs Source Unavailable (`test_case3_no_rows_vs_source_unavailable`)**
   - Distinguishes empty query results (no rows found) from unreachable sources (`unanswerable`).
   - Invariant: `evaluation_limits` enforces `unanswerable` sources remain unknown, preventing affirmative/negative absence claims (flagged by `unsupported_unanswerable_claims`).

4. **Case 4: Output Cut-Off at Token Limit (`test_case4_synthesis_cutoff_emits_error_not_verdict`)**
   - Synthesis hits 16,384 token limit (`stop_reason=length`).
   - Invariant: Raises `CutOff`, emits `error` event carrying `cut_off` metadata (stage, loop, prompt tokens), and strictly suppresses partial `verdict` emission.
